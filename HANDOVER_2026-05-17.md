# Everywear Handover

Date: 2026-05-17
Status: Active implementation handover

## 1. What Is Now Real

### 1magen

`1magen` is now working locally for the base image-generation path.

Validated:

- automatic model provisioning
- SHA256 verification
- model load
- text-to-image generation
- output preview
- output save to `Pictures\Everywear`

The canonical runtime decision is now locked:

- `1magen` is a `Z-Image` applet
- VRAM gating selects the weight tier inside `Z-Image`
- `1magen` style patches must explicitly work with `Z-Image`

Current intended stack:

- `z_image_turbo-Q8_0.gguf` or `z_image_turbo-Q4_K.gguf`
- `Qwen3-4B-Instruct-2507-Q4_K_M.gguf`
- `diffusion_pytorch_model.safetensors`

### 1magen UI

The workbench has been simplified toward the desired product shape:

- prompt
- optional source image
- negative prompt for pure txt2img
- resolution dropdown
- output folder
- seed
- large primary generate action
- output preview

Visible placeholders now exist for:

- `Style Patch (LoRA)`
- `Task Shard (Workflow)`

These are UI placeholders only for now.

### 3nvizen

`3nvizen` is now scaffolded as a real Everywear applet conceptually, but not yet functionally complete.

Implemented so far:

- applet manifest
- runtime README / contract
- segment-chain workflow shape
- `uv` Python sidecar scaffold for LTX runtime

Still pending:

- full applet UI
- shell-side sidecar/server lifecycle management
- actual generation integration

### Shell IPC + Engine Dispatch

The shell/app IPC bridge is now envelope-aware.

Implemented:

- per-launch `EVERYWEAR_IPC_SECRET` injection
- signed `AdvertiseCapabilities` verification
- runtime engine registration from advertised capabilities
- heartbeat event tracking through `VramScheduler`
- registry cleanup when the applet event stream closes
- `submit_engine_job` Tauri command that validates a registered ready engine and sends `ExecuteJob` over the authenticated envelope channel

Current limit:

- dispatch targets the currently active applet process only
- multi-applet process pooling and cross-applet job relay are still pending
- plan queueing, entitlement-manifest validation, cold StartInference/Warmup routing, and event relay back to requesting applets are still pending

### Data Migration

The dedicated `crates/data-migration` crate now owns Phase 5 filesystem migration logic.

Implemented:

- model migration from legacy S3 Gener8 paths into Everywear model paths
- library/settings/audio migration into Everywear data/config paths
- dry-run safety mode
- SHA256 verification
- Windows junction creation for old paths
- RFC3339 migration receipt timestamps

## 2. Important Architectural Locks

### 1magen patch compatibility

This rule is now simple and should remain strict:

- if a style patch is not explicitly `Z-Image` compatible, it is not a `1magen` patch

Do not blur this with:

- Qwen-Image patch assumptions
- Flux patch assumptions
- Klein patch assumptions

### Style Forge

`Style Forge` should be a separate training lane from `1magen`'s lightweight runtime lane.

Training lane:

- Python sidecar
- `uv`
- full `safetensors` Z-Image assets
- LoRA training tooling

Runtime lane:

- applet-first local generation
- provisioned GGUF-oriented stack

Do not attempt to train patches against GGUF runtime weights.

## 3. Local Training Feasibility

Current read:

- local Z-Image style-patch training is viable
- `24 GB VRAM` is the recommended floor for a productized user experience
- `12 GB VRAM` appears possible for smaller jobs with careful settings
- `32 GB+` is comfortable

Reasonable first jobs:

- `20-100` curated images
- `800-3000` steps
- rank `8-32`
- batch size `1`

Likely open tooling path:

- `Tongyi-MAI/Z-Image-Turbo`
- `ostris/ai-toolkit`
- `ostris/zimage_turbo_training_adapter`
- optional `DiffSynth-Studio/Z-Image-Turbo-DistillPatch`

## 4. Model Storage

The Everywear-wide shared model tree exists through `everywear-paths` and the shared `model-manager` crate.

Current reality:

- new shared crates use `everywear_paths::models_dir()`
- `crates/data-migration` can move legacy S3 Gener8 models into `models/gener8`
- applet-specific runtime cleanup may still be needed where older applet-local paths remain

This is now mostly a wiring/cleanup task, not a blocker to current `1magen` generation.

## 5. Repo / Push State

The current workspace contents do not expose `.git` metadata from this environment.

That means:

- docs can be updated
- files can be prepared
- but an authenticated `git add / commit / push` cannot be completed here unless the working tree is reattached to the actual git repository metadata

Target remote provided:

- `https://github.com/BAIS1C/everywear`

If the local checkout is reattached or opened from the real repo root, the likely next command sequence is:

```powershell
git status
git remote add origin https://github.com/BAIS1C/everywear.git
git fetch origin
git checkout -b feature/everywear-zimage-runtime
git add .
git commit -m "Stabilize 1magen Z-Image runtime and scaffold 3nvizen"
git push -u origin feature/everywear-zimage-runtime
```

If `origin` already exists, skip the `git remote add` step.
